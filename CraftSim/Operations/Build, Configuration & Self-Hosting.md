## 1. Build & test pipeline (.NET 10)

```bash
./runprebuild.sh               # build Prebuild, regenerate every .csproj + OpenSim.sln from prebuild.xml, write compile.sh
dotnet build OpenSim.sln       # primary build (CLAUDE.md "Build Commands")
./compile.sh                   # wrapper generated by runprebuild.sh (msbuild Restore + Build, Release)
./build.sh                     # what CI runs: prebuild + `dotnet msbuild OpenSim.sln /t:Restore,Build /p:Configuration=Release`
./check.sh [--filter "Name~X"] # build OpenSim.sln, then dotnet test OpenSim.Tests (extra args) + CraftSim.SmokeTests
./test.sh                      # separate Release msbuild + vstest path for both test projects
```

- `runprebuild.sh` (default branch) copies `bin/System.Drawing.Common.dll.linux` over `bin/System.Drawing.Common.dll`, builds `Prebuild/src/Prebuild.csproj` into `bin/`, runs `dotnet bin/prebuild.dll /target vs2022 /targetframework net10_0 /excludedir = "obj | bin" /file prebuild.xml`, then **writes `compile.sh`**. `./runprebuild.sh clean` / `autoclean` run prebuild `/clean`.
- `check.sh:18` runs `./runprebuild.sh` automatically **only if `OpenSim.sln` is missing**. `compile.sh` and `test.sh` do not.
- `build.sh` is the CI entry point. The `Makefile` still drives `nant` (legacy, not the real build path).
- Windows: `BUILDING.md` documents `runprebuild.bat` + `compile.bat`, then `cd bin; dotnet OpenSim.dll`. Linux/macOS also need `libgdiplus` (`apt-get install libgdiplus libc6-dev`).

### Critical build rules & gotchas
1. **Generated projects are untracked.** `OpenSim.sln` and all prebuild-generated `.csproj` are not in git (CLAUDE.md, change of 2026-10-01). `git ls-files '*.csproj'` shows exactly nine tracked: `Prebuild/src/Prebuild.csproj`, `tasks/ZEngineCompileTest`, `tasks/ZEngineRuntimeBench`, `tasks/probe/invprobe`, `tests/CraftSim.SmokeTests`, `tests/OpenSim.Tests`, `tests/OpenSim.Tests.Common`, `tests/ubode/managed/RecoveryChecks`, `tests/ubode/performance/PerformanceChecks`.
2. **NuGet/Framework references live in `Directory.Build.props`**, never in a generated `.csproj` (prebuild has no `PackageReference` concept; a package added to a generated project is silently lost, symptom `CS0234 ... 'ML'`). Actual contents:

   | Project(s) | Reference | Lines |
   |---|---|---|
   | `OpenSim.Region.ScriptEngine.Shared.Api` | `Tesseract 5.2.0`, `Microsoft.ML.OnnxRuntime 1.28.0`, `PdfPig 0.1.16` | 17-19 |
   | `OpenSim.Region.OptionalModules`, `OpenSim.Tests` | `DotRecast.Core/Recast/Detour/Detour.Crowd 2026.1.3` (pathfinding) | 28-31 |
   | `OpenSim.ApplicationPlugins.McpServer`, `OpenSim` | `FrameworkReference Microsoft.AspNetCore.App` | 41 |
   | `OpenSim.ApplicationPlugins.McpServer` | `ModelContextProtocol 2.2.0` | 44 |
   | `OpenSim.Region.CoreModules` | `SkiaSharp` + `SkiaSharp.NativeAssets.Linux` `4.153.1` (text-to-image; GDI+ cannot read WebP) | 52-57 |

   Also: `Deterministic=true`, `ContinuousIntegrationBuild` auto-set when `CI=true`, `RestorePackagesWithLockFile=true` (so `packages.lock.json` files exist), and a `CopySkiaSharpNative` target that copies `libSkiaSharp.so` next to `OpenSim.dll` after build.
3. **Test projects are not in `OpenSim.sln`.** Run them by path:
   ```bash
   dotnet test tests/OpenSim.Tests/OpenSim.Tests.csproj
   dotnet test tests/CraftSim.SmokeTests/CraftSim.SmokeTests.csproj
   ```
   `check.sh` builds `OpenSim.sln` first on purpose: tests load plugin assemblies by name from `bin/`, so a test-only build leaves stale DLLs and surfaces as unrelated `NullReferenceException`s.
4. **CI** (`.github/workflows/craftsim-net10.yml`): ubuntu-latest, `setup-dotnet 10.0.x`, `apt-get install libgdiplus`, `bash build.sh`, then both test projects in `Release`. `libgdiplus` is mandatory, otherwise the five `osPlot`/`ChartRenderModule` tests fail with `DllNotFoundException`.
5. **SDK pin** (`global.json`): `version 10.0.100`, **`rollForward: latestFeature`**, `allowPrerelease: false`. Runtime: `bin/OpenSim.runtimeconfig.json` targets `net10.0` with `Microsoft.NETCore.App` **and** `Microsoft.AspNetCore.App` 10.0.0.
6. **Version**: `OpenSim/Framework/VersionInfo.cs:32-33` -> `VersionNumber = AssemblyVersionNumber = "1.1.0"`.
7. **Recorded results (not re-run)**: CLAUDE.md states last verified build "0 errors, 0 warnings (2026-10-01, SDK 10.0.400)" and tests 477/479 + 2/2; the one failure is `ZResetLoopTest.Test27CopiesWithoutBrakeSaturateWorkers` (load-sensitive threshold, passes in isolation). **(unverified: current pass/fail)**.

## 2. Running the server & ops scripts

Always start through **`bin/opensim.sh`** (`cd bin && ./opensim.sh`), not bare `dotnet OpenSim.dll`:
- `opensim.sh:2` `ulimit -s 1048576` (1 GiB stack limit).
- `opensim.sh:10` `export LD_PRELOAD=.../lib64/libwrap_memcpy.so`: the shipped `libBulletSim.so` references `__wrap_memcpy` without providing it (physics stepping would die with `undefined symbol: __wrap_memcpy`). The shim is built from `bin/lib64/wrap_memcpy.c`.
- `opensim.sh:12` runs `preflight.sh || true`, then `exec dotnet OpenSim.dll "$@"` (line 14).
- It does **not** set `DOTNET_gcServer` (removed 2026-07-15; env vars override `runtimeconfig.json`).
- **`bin/start-craftsim.sh`** (headless): needs `CRAFTSIM_API_TOKEN`, runs `./opensim.sh` inside a detached **tmux** session `opensim` (output tee'd to `OpenSim-headless.log`), waits up to 120 s for the log line `Running on main`, then starts `python3 craftsim-api.py` on `${CRAFTSIM_API_BIND:-127.0.0.1}:${CRAFTSIM_API_PORT:-8080}` (`POST /broadcast`, bearer token). `craftsim-api.py` was **not found** in the repo tree **(unverified where it lives)**.

### `bin/preflight.sh` (warn-only; `--strict` exits 1 on any warning)
Checks in order: (0) every `${Secrets|X}` used by `OpenSim.ini` is defined and `Secrets.ini` is mode 600/400; (1) when `physics` resolves to `bulletsim` (reads `OpenSim.ini`, falls back to `OpenSimDefaults.ini`): `libBulletSim.so` needing `GLIBC_2.38` vs host glibc, and `lib64/libwrap_memcpy.so` present; (2) `DefaultScriptEngine = "YEngine"` without `[YEngine] Enabled = true`; (3) `[OSSL] TesseractDataPath` is a directory; (4) shipped scripts call `osJson*` but `[JsonStore] Enabled` is not true; (5) MySQL in use (`OpenSim.Data.MySQL` in `OpenSim.ini`) and no `*.sql.gz` newer than 7 days in `bin/backups` (`PREFLIGHT_SKIP_BACKUP=1` silences). Prints `[preflight] OK` when clean.

### Database backup / restore (MySQL only)
- **`bin/backup-db.sh`**: connection parsed from `[DatabaseService]` by `bin/db-common.sh`; password goes through a private `0600` temp options file; runs `mysqldump --single-transaction --routines --triggers <db>` to a `.sql.part`, checks the dump's exit status and non-empty output, then gzips atomically to `${BACKUP_DIR:-bin/backups}/<db>-<YYYYmmdd-HHMMSS>.sql.gz`. Retention `KEEP_DAYS` default **14**. Nothing schedules it (cron/systemd is on you). Also exposed as MCP tool `db_backup` (10-minute kill timeout, `AdminTools.cs:105`).
- **`bin/restore-db.sh <file.sql.gz>`**: verify mode loads into scratch DB `<db>_restorecheck_<pid>` (always dropped) and compares **table counts** with live; never touches live data. `--into-live --yes` restores over live (stop the simulator first). Needs CREATE/DROP on the MySQL user. Per CLAUDE.md both scripts were only exercised against stub `mysql`/`mysqldump`; a real round trip has **not** been run.

## 3. Secrets (`bin/Secrets.ini`)

Template `bin/Secrets.ini.example`; the real file is gitignored, keep mode `0600`. Any ini can use `${Secrets|Name}`.
- Keys in the example: `DatabasePassword`, `EstateOwnerPassword`, `RemoteAdminPassword`, `McpToken`, `JanusApiSecret`, and a commented `OpenRouterKey` (no shipped ini references it; scripts call `osAISetOpenRouterAPIKey` or env `OPENROUTER_API_KEY`).
- Used in `bin/OpenSim.ini`: nine `ConnectionString`s (`Password=${Secrets|DatabasePassword}`, lines 1567-1616), `DefaultEstateOwnerPassword` (547), `[RemoteAdmin] password` (1620), `[Mcp] Token = "${Secrets|McpToken}"` (1626), `JanusApiSecret` (1258).
- Loader: `OpenSim.Framework.SecretsConfig` is called from `ConfigurationLoader.cs:210-225` (simulator; `./Secrets.ini`, overridable by `-secretsfile=<path>` or `[Startup] secretsfile`) and `ServicesServerBase.cs:77,117-119` (Robust; next to the main ini, or `-secretsfile`). Merged after ini files and `config/` drop-ins, before `ReplaceKeyValues`; env and command line still win.
- **Fail-fast**: an undefined `${Secrets|X}` stops startup with a message naming setting and key (`SecretsConfig.FindUndefined`). A missing `Secrets.ini` is fine until something references it.
- **Quoting**: values containing `;` or `#` must be double-quoted (Nini treats them as comments); a `;` in a DB password would also end the connection-string field.
- Shell side: `bin/secrets-common.sh` (POSIX sh) resolves references for `db-common.sh`/`backup-db.sh`/`restore-db.sh`/`preflight.sh`; `SECRETS_FILE` overrides the path. The MCP bridge reads the same file (see [[MCP Server & Live Diagnostics]]).
- History caveat (CLAUDE.md): history was **not** rewritten; the old MCP token is in 5 earlier commits and the Janus value in 2. Treat as exposed and rotate.

## 4. Deployment topologies

### What the tracked `bin/OpenSim.ini` actually says
- `[Architecture] Include-Architecture = "config-include/StandaloneHypergrid.ini"` (line 1527); alternatives are listed commented.
- `[Const] BaseHostname = "<grid-host>"` (57), `PublicPort = "9000"` (71). `StandaloneCommon.ini:43,57` set `GatekeeperURI` / `HomeURI = "${Const|BaseURL}:${Const|PublicPort}"` (so `http://<grid-host>:9000` as committed).
- `DefaultScriptEngine = "ZEngine"` (284); `[ZEngine] Enabled = true`, `NumWorkers = 4`, `MaxEventSliceSeconds = 30`, `MaxWorkerQuantumMilliseconds = 5`, `ZEXT = true` (1040-1080); `[YEngine] Enabled = false` (1096). `OpenSimDefaults.ini` leaves `DefaultScriptEngine` commented (application fallback is `YEngine`, per `BUILDING.md`).
- Physics default in `OpenSimDefaults.ini`: `physics = ubODE` (302), `meshing = ubODEMeshmerizer` (274). BulletSim is selectable (see [[Performance & Benchmarks]]).
- DB: MySQL, `Data Source=localhost;Database=opensim;User ID=opensim;...Old Guids=true;SslMode=None;`, `StorageProvider = "OpenSim.Data.MySQL.dll"` (1594). `BUILDING.md` says SQLite is the default for a *fresh* standalone (`StandaloneCommon.ini.example`).
- `[Mcp] Enabled = true, Port = 80, Token = ${Secrets|McpToken}` (1623-1626); `[RemoteAdmin] enabled = true`, `access_ip_addresses = "127.0.0.1,::1"`; `[DbConsole] Enabled = true`, `AllowWrite = false` (1569-1577); `[Statistics]`/`[Monitoring]` enabled; `[NPC] MaxNumberNPCsPerScene = 150` (1459).
- Tracked `bin/Regions/Regions.ini`: `[Nexus]` Location `1000,1000`, **1024x1024**, `InternalPort = 9000`, `ExternalHostName = <grid-host>`, `MaxAgents = 250`; `[pakkio2]` `1004,1000`, 256x256, `InternalPort = 9001`, `MaxAgents = 250`.

### The production host differs (CLAUDE.md only; **unverified from this repo**)
Public identity `http://<grid-host>:<grid-port>`, grid nick `craft-sim`, regions on UDP 9200/9201, MCP on `9200/tcp`, `GatekeeperURIAlias`/`HomeURIAlias = s60.craft-world.org:<grid-port>`, `[Mcp] ListenAddress = 127.0.0.1`, region named `PKC`. None of <grid-port>, `PKC` or a `ListenAddress` appears in the tracked `.ini` files; those live in uncommitted host copies. CLAUDE.md also warns the DNS names carry AAAA records for an IPv6 address the simulator does not bind (IPv4 only). Changing the hostname changes the Hypergrid identity and needs a restart.

### Self-hosting a split grid (`Robust.dll` + `OpenSim.dll`, see `SELF_HOSTING.md`)
1. Copy `Robust.ini.example -> Robust.ini` (or `Robust.HG.ini.example` for HG), `OpenSim.ini.example -> OpenSim.ini`, `bin/config-include/GridCommon.ini.example -> GridCommon.ini`.
2. In `[Architecture]` enable `config-include/Grid.ini` (or `GridHypergrid.ini`), not a Standalone include as well.
3. **DefaultRegion**: in `Robust.ini` `[GridService]`, `Region_<YourRegionName> = "DefaultRegion"`, otherwise new accounts with no last region fail login with "destination not found".
4. Start `dotnet Robust.dll` first (ports 8002 public / 8003 private), then `./opensim.sh` (region port 9000 by default).
5. Robust also resolves `${Secrets|X}`.
